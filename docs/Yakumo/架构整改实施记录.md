# Yakumo 架构整改实施记录

更新时间：2026-09-05

本文件记录架构审计后的实际整改进度。它以当前代码为准，不把设计文档中的目标
状态当作已经完成的实现。

## 1. 当前基线

### 1.1 已完成或已有实现

- `InteractionTurnState`、`InteractionStreamState` 和 `InteractionTurnCompletionState`
  已经承载大部分 Interaction turn、流式、完成和输出状态。
- Core delegation、route decision、assistant artifact、visible output、
  stream buffer 和生命周期状态已有 typed state 入口。
- `TurnExecutionScope` 已负责一轮内部异步任务的登记、取消和关闭。
- `PluginExecutionRuntime` 已具备 lease、draining、Gate 和 delivery ledger
  等运行时保护。
- T1/T2 产物已有 delivery key、reservation、duplicate fingerprint 和 T1
  boundary freeze 等保护。
- 主要 Router、Planner、Persona、Tool loop、ProcessStage 和 Personal Runtime
  阶段已经使用 `TurnDeadlineBudget`。

### 1.2 尚未完成

- `event.extra` 仍承载兼容引用、诊断、配置、Provider 请求和少量专属 Runtime
  状态；第一阶段已完成明确属于 Interaction turn 的字段分类和主路径迁移。
- `event.send`、`event.send_streaming` 和 `event.complete_visible_turn` 仍通过
  `MethodType` 进行兼容拦截。
- Output Controller、Plugin Artifact Delivery、Delayed Delivery 和
  `TurnDeliveryCoordinator` 的公共状态边界尚未形成一份明确的契约。
- `astr_main_agent.py` 仍同时装配 Provider、Conversation、Prompt、Capability、
  fallback、Execution 和 Agent Runner。
- CapabilitySnapshot、ToolSet、Prompt tool schema、`CoreExecutionSpec` 和
  `ProviderRequest` 之间仍存在转换成本。
- `parallel_plugin_runtime_enabled` 默认仍为 `False`，并行插件路径尚未通过真实
  私聊、群聊、reload、取消和迟到输出验收。

### P1：Turn 状态收敛

状态：第一阶段已完成，进入专属 Runtime 边界和端到端验证。

处理规则：

- 新增状态必须进入 `InteractionTurnState` 或明确的专属 Runtime owner。
- `event.extra` 中的内部镜像字段不得继续新增。
- 兼容字段只能保留为引用、适配标志或诊断信息。
- 删除字段前必须确认仓库内、测试和已知外部插件没有调用者。

2026-09-05 已完成第一阶段的第二批迁移：

- 立即回复发射、入站媒体物化、STT 成功/失败、Router 失败和上下文节点、
  Core Planner 失败/Persona 恢复、Expression 失败/fallback 已由
  `InteractionTurnState` 作为主事实源。
- Conversation 提交的 turn/conversation 标识、固定会话约束、延迟历史跳过原因、
  delivery metadata、Conversation history failure、turn finalization failure 和
  turn postprocess failure 已有 typed owner。
- `conversation_history.py`、`delayed_plugin_delivery.py`、`middleware.py` 和
  `output_controller.py` 的主路径通过 `turn_state` helper 读写；旧 extra 只作为
  分支事件、外部集成和兼容测试的投影。
- `InteractionTurnState` 的兼容投影仍保留，暂不删除 `_interaction_*` key；这不再
  等同于存在第二条内部主事实路径。
- Prompt/result contributor failures、plugin handler metrics、plugin output
  transaction、effect calls 和 ProviderRequest 仍分别归属 contributor 诊断、
  Plugin Runtime/Output Controller 或 Provider 边界，本阶段不强行并入 TurnState。

### P2：Output Runtime

状态：边界收敛进行中，尚未进行物理合并。

目标状态：

```text

  -> OutputArtifact
  -> DeliveryReservation
  -> PlatformDelivery
```

Output Adapter 替代事件方法替换。第三步完成兼容验证后，再决定哪些类可以物理合并。

2026-09-05 已完成本批次的第一项边界收敛：

  `_interaction_output_interceptor_installed` 字段继续作为兼容投影保留。

  `plugin_branch` 和外部兼容调用不需要同步迁移。

  完成 Output Adapter，也没有改变官方 Event API 行为。
- `tests/unit/test_astr_message_event.py`：89 passed；相关文件 Ruff 检查通过。

### P5：并行插件运行时

状态：默认关闭，等待真实验收。

验收矩阵至少包括：

| 场景 | 必须确认 |
|---|---|
| 私聊普通 turn | Personal、Router、Plugin 是否按预期并发启动 |
| 群聊普通 turn | 触发、续接 owner 和静默规则是否正确 |
| `HANDLED` / `STOPPED` | pending Persona 是否被抑制，已发送回复是否不被撤回 |

## 3. 变更纪律

- 每批次只修改一个主要 owner 边界。
- 所有迁移保留可回滚开关。
- 不以减少文件数量作为成功标准。
- 不把静态代码推断当作端到端验证结果。
- 代码修改前先更新调用图和影响面。
- 每个删除候选必须有调用者清单和退出条件。

## 6. 本轮代码整改复核

本轮只处理输出拦截依赖的原始平台方法引用，未扩大到 Output Controller、
Delayed Delivery、Plugin Artifact Delivery 或并行插件运行时。当前可确认的结论：

- 方法引用的直接写入点已收敛到 `AstrMessageEvent.install_interaction_output_hooks`。
- `send_message_with_extras` 和 `send_interaction_streaming` 不再直接读取匿名
  `extra` key，而是通过 Event 层 getter 获取原始方法。
- 兼容字段仍然存在，因此这不是删除兼容边界，也不是对外 API 迁移。
- 新增的 Event 层存储属于平台事件的兼容基础设施，不承载 turn、delivery 或
  controller 状态；后续仍需继续处理 controller 引用和输出状态的 owner 契约。
