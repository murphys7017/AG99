更新时间：2026-09-19

本文件记录架构审计后的实际整改进度。它以当前代码为准，不把设计文档中的目标
状态当作已经完成的实现。

## 2026-09-19 收口切片：InteractionTurnState 主写者迁移

本切片开始执行近期推进队列第 1 项，未引入新的对外协议、输出路径或 Executor Body。

- `InteractionTurnState` 现在由 `AstrMessageEvent._interaction_turn_state` 持有；
- `_interaction_turn_state` extra 仍保留为单向兼容投影，旧事件可被读取并提升到 typed
  owner；
- `CoreExecutionSpec` 迁入 `InteractionTurnState.core_execution_spec`，Core 事件投影、
  取消和 Ledger 结算统一通过 typed accessor 读取；
- 插件输出事务的 active/start/pending artifacts 迁入 `InteractionTurnState`，旧事务
  extra 只保留兼容投影；
- Plugin branch event 显式清空 typed Interaction state，避免父事件与分支共享可变 turn
  事实；
- 相关 Core/Interaction/Plugin 测试 80 项通过，compileall 和 diff check 通过。

本切片只证明主写者迁移没有破坏现有路径，不代表 `event.extra` 已经全部清理。下一批
仍需继续盘点 `ProviderRequest`、输出状态和插件专属运行时字段，并按同样方式逐项迁移。

## 2026-09-19 全局架构收口复核

本轮只完成源码与文档审阅，没有修改业务代码。审阅结论是：当前已完成的各个局部
切片不能直接相加为“整体架构完成”。项目需要先进入一段收口期，避免新的局部优化
继续增加 owner、兼容镜像和旁路输出。

### 当前冻结的长期 owner

- `InteractionTurnState`：InteractionTurn 内部事实和状态转换；
- `InteractionOutputController` / 后续 `OutputRuntime`：可见输出意图、产物、投递和完成；
- `CoreExecutionHead`：CoreExecution 命令、事件、取消和终态事实；
- `CapabilitySnapshot`：一次执行的可见能力、可执行能力、策略和来源。

### 收口期的非目标

- 不新增 Executor Body；
- 不新增第二条 Personal/Core 对外输出路径；
- 不把 `CoreExecutionHead` 提前改名为 Backend；
- 不在没有真实验收前删除旧 Handler-first 路径；
- 不把 T1/T2 风险、输出边界复杂度或身份数量直接表述为已发生线上故障。

### 收口期验收门槛

在继续 Executor 解耦前，需要完成：

1. `event.extra` 读写和单向兼容投影清单；
2. Output Controller、Plugin Artifact、Delayed Delivery、Turn Delivery 的写入规则；
3. Handler-first 与协调 Plugin Runtime 的真实私聊、群聊、取消、reload、迟到输出、
   重复投递验收；
4. `astr_main_agent.py` 的 Provider/Prompt/Capability/Execution 装配调用图；
5. `InteractionTurn -> PluginInvocation/CoreExecution -> OutputArtifact` 身份关系表；
6. Cron/主动任务与普通 Interaction 的输出、TTS、历史和完成回执一致性验收。

未满足这些门槛时，Phase 9 仍处于 Native 进程内事实边界阶段。

### 2026-09-14 Phase 9 第八个实现切片

- Lifecycle 的旧事件入口与 Head 共享同一发布路径；Head 订阅者逐个隔离异常，单个观察者失败
  不会阻断执行状态、其他订阅者或 Interaction turn journal。
- 绑定时校验 `CoreExecutionHead`、`CoreExecutionLifecycle` 与 `CoreExecutionSession` 的对象和

- 事件重放键从“所有非 progress 事件按类型唯一”收紧为：状态事件按类型首写、progress 保留
  每次观察、artifact 按稳定 `artifact_id` 去重；Native 最终结果使用 `final_response` 作为聚合
  artifact ID。

本切片仍不引入队列、Executor 选择、Artifact owner 迁移或新的对外输出路径。

### 2026-09-14 Phase 9 第九个实现切片

- Interaction execution journal 与 trace 明确作为 Head 的本地 event consumer；直接经 Head 或旧
  Lifecycle 入口写入的事实都会共享同一 Session 编号和投影路径。
- Native compatibility helper 在存在 Head 时只提交事实，不再自行追加第二份 journal；没有 Head 的
  兼容桥接仍保留原有行为。
- `cancelled` 终态先发布并投影，再请求 Executor stop；stop callback 失败作为紧随终态的独立
  trace 诊断记录，不会阻断或延迟取消收敛。
- journal 满载时优先淘汰 progress；终态到达而没有 progress 时淘汰最旧 artifact，因此终态和
  trace 不会因 artifact 饱和丢失。

本切片不引入队列、跨进程通信、Personal 可见输出、Ledger owner 迁移或新的 Executor Body。

### 2026-09-14 Phase 9 第十个实现切片
